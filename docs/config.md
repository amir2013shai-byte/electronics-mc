# config.yml, practical work и готовые сборки

Файл: `plugins/Electronics/config.yml` (полный с комментарями создаётся при
первом старте). Все значения применяются по `/elec reload`.

## render

| ключ | по умолчанию | что делает |
|---|---|---|
| `render.mode` | `display` | `display` — ItemDisplay/TextDisplay над платой; `none` — только предмет/блок-модель |
| `render.scale` | `0.55` | размер модели компонента (1.0 = блок) |
| `render.offset-y` | `0.06` | подъём над платой |
| `render.block-light` | `true` | подсветка блока под LED/лампой (через `BlockData#setLight`) |
| `render.view-range` | `48.0` | дистанция показа дисплеев игроку |
| `render.text-labels` | `true` | подписи значений над приборами |

## scope — экран осциллографа

| ключ | по умолчанию | что делает |
|---|---|---|
| `scope.text-size` | `0.24` | масштаб `TextDisplay`, которым нарисована трасса (у Spigot у дисплея размера текста нет — он сидит в трансформации): 20 знаков Брайля = 40 пикселей растра. При 0.24 это влезает в грань блока, при 0.3+ картинка вылезает за прибор, при 0.18 точки сливаются |
| `scope.refresh-ticks` | `2` | как часто перерисовывать экран (1 = каждые 50 мс — живая трасса, но пакет на каждый экран каждый тик; 2 = вдвое дешевле) |
| `scope.afterglow` | `true` | послесвечение: прошлый кадр дорисовывается через каждый третий столбец, поэтому редкий импульс не пропадает между обновлениями |

## blocks

| ключ | по умолчанию | комментарий |
|---|---|---|
| `blocks.base` | `SMOOTH_QUARTZ_SLAB` | «плата», на которой стоят детали. ресурспак перекрашивает её в зелёную плату с дорожками |
| `blocks.pedestal` | `POLISHED_BLACKSTONE` | подставка под платой |
| `blocks.require-pedestal` | `true` | ставить детали только когда под платой есть блок |

Если хотите «настоящие» блоки вместо подставки — поменяйте `blocks.base` на
любой неполный блок (например `OAK_SLAB`); ресурспак переопределяет модель
только для кварцевого полублока, для других придётся скопировать
`assets/minecraft/blockstates/<блок>.json` из собранного пака.

## simulation

| ключ | по умолчанию | смысл |
|---|---|---|
| `simulation.continuous` | `true` | пересчёт каждый тик; `false` — только по событиям/`/elec sim` |
| `simulation.components-per-tick` | `900` | бюджет тика: сколько компонентов обработать за раз |
| `simulation.max-nodes-per-island` | `260` | предел узлов в одном «острове» цепи |
| `simulation.max-components-per-island` | `400` | предел деталей в острове |
| `simulation.solve-passes` | `2` | итерации нелинейного решателя (LED/транзисторы) |
| `simulation.faults` | `true` | КЗ, перегрев, пробой, сгорание |
| `simulation.conductor-ohm` | `1e-6` | сопротивление «идеального» провода |
| `simulation.leak-ohm` | `5e7` | утечка между несоединёнными узлами (нужна, чтобы матрица не была вырожденной) |
| `simulation.generator-period-ticks` | `10` | период меандра генератора (10 тик = 5 Гц) |
| `simulation.solar-day-voltage` / `-night-` | `5.0` / `0.05` | солнечная ячейка |
| `simulation.time-step-ms` | `50` | шаг интегрирования конденсаторов |
| `simulation.bench-wiring` | `false` | legacy-режим: соединять по всем 6 граням (замыкает цепочки — только для «песочницы») |

## deposits: недра (руда как функция координат)

```yaml
deposits:
  enabled: true
  seed: 0            # 0 = сид мира; число — воспроизводимые недра
  chunk-chance: 0.18 # доля чанков с жилой
  y-min: -48         # низ пояса
  y-band: 40         # высота пояса: и низ, и верх жилы держатся внутри
  vein-size: 14      # блоков руды в жиле
  vein-jitter: 26    # разброс размера (14…40)
  yield-per-block: 1 # кусков руды с одного блока
```

Жила нигде не лежит: она вычисляется из `(chunkX, chunkZ, seed)`, поэтому
её не надо генерировать, и она не «портится» от выгрузки чанков. На диске
живёт только состояние добычи — `plugins/Electronics/deposits.json`
(вскрытые жилы `R <cx> <cz>` и выбранное количество `M <cx> <cz> <mined>`).
`enabled: false` выключает геозонд и выдачу руды: копка породы снова отдаёт
обычную породу (цепочку пайки это не ломает — детали останутся в каталоге).


## Практические работы: `plugins/Electronics/labs/*.yml`

```yaml
name: "Светодиод и гасящий резистор"        # показывается в /lab list
task: >
  multiline текст задания
expect: "LED горит, I ~ 20 мА, P ~ 0.05 Вт"  # что сверяем (текстом + составом)
components:                                  # список материалов (id: количество)
  battery_9: 1
  resistor_330r: 1
  led_red: 1
  wire_red: 2
  ground_bus: 1
signature: ""                                # эталонная топология; пусто = не сверять
```

* `/lab start <имя>` — показать задание и (при праве `electronics.give`)
  выдать перечисленные компоненты.
* `/lab check <имя>` — сверить цепь под прицелом: состав + `signature`
  (сигнатура netlist'а, координатно-независимая: «типы и соединения», а не
  позиции). Совпало — «Работа зачтена».
* `/lab save <имя>` — записать текущую цепь как эталон в тот же файл.

## Готовые сборки: `plugins/Electronics/builds/*.json`

```json
{
  "name": "RC-цепочка: заряд конденсатора",
  "origin": [0, 0, 0],
  "blocks":     [{"d": "bench", "p": [0, 0, 0], "host": true}],
  "components": [{"d": "power_supply", "p": [0, 1, 0], "o": 1, "t": 1.0}]
}
```

* `p` — смещение от `origin`, `o` — ориентация (0 north, 1 east, 2 south,
  3 west, 4 up, 5 down), `t` — положение подстроечника (0..1).
* **Важно про `o`:** контакт детали «смотрит» в сторону её ориентации, поэтому
  соседние детали должны быть ориентированы навстречу (0/2 — по Z, 1/3 — по X).
* `/elec build <имя>` — поставить под прицелом; с консоли
  `/elec build <имя> <мир> <x> <y> <z>`; `/elec build save <имя>` — сохранить
  свою цепь как новый пресет.

## kinetics

| ключ | по умолчанию | комментарий |
|---|---|---|
| `kinetics.enabled` | `true` | считать ли механику вала. Выключено — `KineticEngine.tick()` ничего не трогает: мотор остаётся «напряжённым» мотором из v1.3.1 (обороты из напряжения, ЭДС из прошлаго такта), детали привода лежат как декорации. |
| `kinetics.break-blocks` | `true` | ломать ли блоки, до которых дотянулся инструмент. С выключенным механизмом считается полностью (обороты, момент, нагрев обмотки, ток), но мир не меняет — для тестового сервера и для «станка-витрины». |
| `kinetics.carriage-move` | `true` | переставлять ли каретку на метр вперёд, когда бревно перед пилой кончилось. Полезно выключать, если привод запитан подводящим проводом сбоку: уехав на метр, мотор отрывается от цепи и встанает («тяга 0 Н»). |
| `kinetics.blocks-per-minute` | `40` | сколько блоков механизм может сломать за минуту. Окно в 60 с и счётчик — **у каждого механизма свои** (`Rig.breaks`): две лесопилки пилят по 40 каждая. `1` — почти останавливает работу, `1000` — снимает ограничение вовсе. |

Считается по числу реально сломанных блоков, а не по попыткам удара. Когда
лимит выбран, механизм не молчит, а пишет в подсказку
`лимит 40 блоков/мин на механизм (config: kinetics.blocks-per-minute)`; с
`break-blocks: false` — `режим без разрушений (config: kinetics.break-blocks=false)`.
Блок, который упал сам (отрезали опору), считается отдельной строкой:
`срублено блоков: N — дальше работала гравитация`.

## battery — свинцовый аккумулятор (v1.6.0)

| ключ | по умолчанию | комментарий |
|---|---|---|
| `battery.charge-efficiency` | `0.95` | доля ампер-часов, которая возвращается в банк. Час заряда током 1 А при 0.95 даёт 13.4 % вместо 14.3 % (проверка `TestBattery`: «КПД заряда 95 %»). 0.8 и ниже — «банка греется вместо зарядки»; 1.0 — учебный «идеальный» случай, потерь на заряд нет. |
| `battery.self-discharge-per-day` | `4.8` | саморазряд, % ёмкости в сутки. С 4.8 % банк, простоявший 60 суток, теряет ёмкость с 7.00 до 5.36 А·ч. `0` — банка лежит заряженным сколько угодно (удобно для длинных уроков). |
| `battery.sulfation-per-hour` | `2.0` | сколько % ёмкости уходит за час простоя **глубоко разряженным** (soc < 20 %). 2 %/ч — сутки в ноль стоят около половины ёмкости и деталь становится `burnt`; 0 — «сульфатации нет», разряженная банка ждёт сколь угодно долго. |

Значения читаются при каждом шаге, так что менять их можно на лету; ноль или
отрицательное число = «идеальный» аккумулятор. Остальные параметры банки — не
конфиг, а реестр: `capacity_ah` (7) и `peukert` (1.25) лежат в
`shared/components.json` рядом с номиналами, потому что это свойство детали, а
не режима сервера. Предел заряда выводится из ёмкости: 1C, то есть 7 А; кипение
напряжением — 14.4 В (оба порога — константы `Battery.java`, их менять нужно с
офлайн-тестом: `java -cp build/tb TestBattery`).

## selftest

| ключ | по умолчанию | комментарий |
|---|---|---|
| `selftest` | `false` | через 3 секунды после старта нарисовать тестовую цепь в GUI-редакторе, просчитать её тем же решателем и сверить показания; плюс проверка каталога (у каждого предмета — карточка и описание), проверка экрана осциллографа в мире и четыре строки про аккумулятор (разряд, штатная зарядка, перезаряд, круговой прогон через `registry.json`). В консоли появляется `PASS`/`FAIL`; на v1.6.0 — 28 строк PASS и ни одного FAIL. Ставят `true` после обновления плагина или после своих правок физики. |

Тот же вызов вручную: `/elec selftest` (работает и с консоли).
